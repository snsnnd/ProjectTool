## 2. 逐项审计明细

### A1 Project 未参与 revision concurrency control

- **文档承诺**：`docs/03-data-model.md` §2 “所有对象统一 Header：version / rev / created_by / updated_by”；`docs/05-interfaces.md` §3 “修改类方法可选 expected_rev”。
- **实际行为**：
  - `domain/project.py` 只有 `schema_version/id/type/name/slug/description/status/created_at/updated_at/metadata`，无 `version/rev/created_by/updated_by`。
  - `storage/transaction.py:54` 对 `PROJECT_TYPE` **跳过 base_rev 校验**。
  - `project.update` 无 `expected_rev`，并发修改静默覆盖。
  - `init_project` 写入的 `project.initialized` 事件 `new_rev=None`。
- **处理**：Project 加入 `version/rev/created_by/updated_by`（按 `ProjectStatus` 语义，不再重复 `lifecycle`）；`project.update(expected_rev=…)`；Transaction 删除 PROJECT_TYPE 特判；init 事件写入初始 rev；doctor 校验 project rev。

### A2 Transaction 无法从多文件中断中恢复

- **文档承诺**：`docs/04-storage.md` §5 “staging 目录残留 = 上次事务中途失败……可直接删除”（把残留一律当作可删除）。
- **实际行为**：
  - `Transaction.commit` 在 `finally` 中无条件 `rmtree(staging)`；若 `os.replace` 在第 N 个写入后异常，已替换的 canonical 文件保留、其余丢失，且 staging 已被删除 → **不可判断、不可恢复**。
  - 没有 manifest、没有 COMMIT marker、没有恢复状态机。
- **处理**：引入 manifest + COMMIT marker + 状态机（prepared → committed → applied）；apply 失败/中断保留事务目录；`storage/recovery.py` 提供 `scan_transactions / recover_transaction / recover_all`，已提交事务 roll-forward、未提交事务安全丢弃；恢复幂等。

### A3 WriteLock 误删活跃锁

- **实际行为**：
  - stale 只按 `mtime > 60s`（`local_state.py:95`），合法长操作可能被抢锁。
  - `__exit__` 无条件 unlink，锁被 B 替换后 A 退出会删除 B 的锁。
  - 锁文件写入了 pid 但从不读取。
- **处理**：锁文件改为 JSON（pid + lock_id + created_at + host）；POSIX 用 `os.kill(pid, 0)` 判活、Windows 用 `OpenProcess` 兼容；**pid 存活则永不偷锁**，仅 pid 死亡/不可解析且超时才回收；释放时仅在 `lock_id` 匹配时删除。

### A4/A5 层级环与 supersede 环

- **实际行为**：
  - Goal：`goal_update` 直接赋值 `parent_goal_id`，无环检测。
  - Task：`_validate_parent_chain` 有链检查但报 `INVALID_ARGUMENT`。
  - Decision：`A supersedes B` 后 `B supersedes A` 可成功，形成环。
- **处理**：新增错误码 `HIERARCHY_CYCLE`（exit 3）；Goal parent、Task parent、Decision supersede 均做链环检测；`parent chain too deep` 保留为损坏保护。

### A6 引用/分配校验不足

- **实际行为**：`resolve` 只按文件名匹配，deleted 对象仍可被新引用；inactive member 可被 assign；closed/cancelled milestone 仍可接收新任务。
- **处理**：新引用禁止指向 `lifecycle=deleted` 对象；禁止把新任务/迁移任务放入 `closed/cancelled` milestone（同值 no-op 除外）；禁止 assign inactive member；已有历史引用不视为错误（doctor warning）。

### A7 Event 契约

- **实际行为**：payload 结构散落代码；无 event 链一致性检查；无不可变性测试。
- **处理**：新增 `docs/08-events.md` 记录 V0 event contract；doctor 校验 `base_rev → new_rev` 链与对象当前 rev；新增事件文件哈希不可变测试；EventStore 不提供任何 update/delete API（仅 migration 允许处理历史格式）。

### A8 Service 拆分与 Registry

- **实际行为**：`application/service.py` 1396 行；`getattr(self, method.replace(".","_"))` 动态分发，无 mutating 元数据。
- **处理**：拆分为 `application/context.py`（共享能力）+ `application/services/*.py`（8+2 领域组）+ `application/registry.py`（显式 MethodSpec：name/handler/mutating/category/description）。`ProjectService.call/handle` 签名与全部 method 名称保持兼容。新增 `system.capabilities`。

### A9 CLI 拆分

- **实际行为**：`cli/main.py` 1380 行。
- **处理**：拆为 `main.py`（Typer root + 注册）/ `common.py`（状态、执行、错误）/ `render.py`（渲染）/ 各域模块；命令名、参数、输出格式保持兼容；CLI 不 import storage。

### A10 Doctor 增强

- **处理**：新增 project header/rev、transaction manifest 与状态、write.lock 健康、event 链一致性检查；每个 check 增加 `repairable` 标记；新增 `pjt doctor --repair` 与 `project.recover`（roll-forward + 清理陈旧锁）。

### A11 静态质量与 CI

- **处理**：`ruff` + `mypy` 加入 dev 依赖并有配置；`.github/workflows/ci.yml` 在 Ubuntu/Windows + Python 3.12 上执行 `ruff check / mypy / pytest`。

### A12 文档措辞

- **处理**：`docs/04-storage.md` 改为明确描述 crash-recoverable（而非完全原子/ACID）；新增 manifest/COMMIT/recovery 协议说明；`docs/02/03/05/06`、`README.md` 同步。

### A13 capabilities

- **处理**：`system.capabilities` 返回 `protocol_version / schema_version / methods / features`，features 全 false（artifact/git/search/web/remote/sync 尚未实现）。

### A14 测试缺口

- **处理**：新增 Project revision、并发 project.update、故障注入（staged/manifest/COMMIT/部分 apply/events 部分 apply/state 失败）、恢复幂等、WriteLock ownership、死 PID、活跃 PID 保护、Goal/Task 层级环、Decision supersede 环、Event 不可变、doctor 事务诊断；全部使用 `tmp_path` + monkeypatch，无 sleep/网络依赖。
